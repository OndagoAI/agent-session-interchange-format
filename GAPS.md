# ASIF 0.3 gaps and implementation status

Reviewed against the current specification and recorded test results on **2026-09-26**.

The OpenAPI-style organization work is complete for the core, continuation profile and destination report: **124 object definitions**, fixed-field tables, linked types and requirements, and **136 schema-validated examples**, including attachment representations and availability states. Object/field links and generated-document freshness are checked. These counts exclude the separately documented package transport objects.

The reference subset now has [Python and standalone TypeScript CLIs](REFERENCE.md), shared continuation tests and local package/signature exchange checks. Both are locally authored; this does not close the independent-evidence gap. The project license is now [MIT](LICENSE).

The remaining work has three distinct meanings: **specification gaps** need portable rules or machine-readable definitions; **implementation gaps** need executable support and broader tests; **evidence/release gaps** need independent exchange or the publication steps already proposed in [governance](GOVERNANCE.md). A missing vendor adapter is not a missing core session field. Passing local tests does not establish general interoperability or permission to execute.

Licensing alone does not satisfy these gates. |

P0 items apply to the stated conformance or release claim. Live import and continuation evidence is needed when claiming those capabilities; it does not require the core specification to define every vendor's native format. P1 capabilities must either have supported, tested semantics or remain explicitly outside the implementation's claimed scope.

The next vendor-neutral work is to map normative requirements to checks, resolve the status and definitions of the neutral configuration dialects, and bring the transport objects into schema/example validation. Vendor adapters and live destination integration remain deferred; independent evidence remains a standardization requirement even while that integration work is deferred.

Evidence: [reference scope and commands](REFERENCE.md), [local reference results](tests/reference-results.json), [continuation checks](tests/continuation-results.json), [object and navigation checks](tests/documentation-results.json), and [implementation record](IMPLEMENTERS.md). All continuation reports in the example corpus are synthetic. The native-agent work above is deliberately deferred while ASIF remains vendor-neutral.
